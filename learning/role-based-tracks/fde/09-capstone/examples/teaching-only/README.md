# Teaching-Only Mini Package

> **Evidence banner:** `SYNTHETIC EXCERPT`, `UNEXECUTED`, `INCOMPLETE BY DESIGN`, `NOT A PASSING CAPSTONE`, `NOT PRODUCTION EVIDENCE`.

This small example shows the expected level of specificity for one conflict and one acceptance thread. It is not a filled answer key, does not resolve the Riverside brief, and cannot be submitted as the capstone.

## Example scope

- one workflow: cited policy answers for authorized editors;
- one conflict: `CON-RIV-001` latency;
- one acceptance criterion: `AC-EX-001`;
- one architecture decision: `ADR-EX-001`;
- one unresolved external-validation request: `VAL-EX-001`;
- recommendation: `HOLD` before customer cohort exposure.

Read the files in order:

1. [ambiguity-and-claim-register.md](ambiguity-and-claim-register.md)
2. [traceability-and-recommendation.md](traceability-and-recommendation.md)

Notice what the example does not do: it does not invent a latency threshold, run a test, choose a cloud SKU, assert customer acceptance, or claim the cited-answer path is ready. The useful output is a bounded next decision with an owner and evidence request.
