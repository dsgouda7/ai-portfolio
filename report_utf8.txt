# Transformer Foundations, Part 1 of 3: Attention and Transformer Blocks

> **Series route:** Part 1 builds attention and the reusable Transformer block. [Part 2](02-decoder-only-language-model.ipynb) turns that block into a causal language model. [Part 3](03-encoder-decoder-and-cross-attention.ipynb) adds bidirectional encoding and cross-attention.

## Why Riverside Needs Transformers

Riverside House is preparing an in-house assistant for its unpublished novel *The Weight of Distant Light*. An editor gives it one manuscript line:

> **"Aria heard the signal aboard Meridian."**

The line is short, but useful editorial work already demands several kinds of reasoning. The assistant must connect **Aria** to the act of hearing, treat **signal** as the thing she heard, preserve the fact that it happened aboard **Meridian**, and notice that moving the same words changes the sentence. Later it must continue the passage one token at a time or transform it under a separate brief without losing those relationships.

An RNN can carry history forward through one recurrent state, but that creates a long sequential path between distant words and limits parallel training. Riverside needs a mechanism that lets each token inspect the other relevant tokens directly, keeps word order visible, and scales those interactions across a manuscript. That mechanism is **attention**; stacking attention with per-token computation, residual paths, and normalization gives us a **Transformer**.

This series follows that one Riverside line from meaning to generation to controlled transformation:

| Notebook | Riverside question | Mechanism we need |
| --- | --- | --- |
| Part 1 | How does each word gather the context that gives it meaning? | Self-attention and Transformer blocks |
| Part 2 | Given the manuscript so far, what token should come next? | Causal decoder and next-token training |
| Part 3 | Given a source passage and an editorial brief, how should the output change? | Bidirectional encoder, causal decoder, and cross-attention |

We begin with a tiny, inspectable vocabulary. The dimensions are deliberately small; the relationships are the same ones Riverside's later language models must learn at production scale.

> **Predict before the architecture:** if the diagnostic source is `[3, 1, 4, 1]` and the required response is `[1, 4, 1, 3]`, where must the first output step retrieve information from? It needs the **last source position**. What representation would let every output step query any source position while still generating the response causally?

That retrieval question is the notebook. We will encode the full source bidirectionally, let the causal decoder query it through cross-attention, and use integer reversal as a transparent routing test. Reversal is a microscope for Riverside's editorial transformation, not a second narrative.

> In 2018, OpenAI's first GPT system made a practical point that still governs base-model construction: the learning objective is only as trustworthy as the text stream delivered to it. Riverside House now applies that lesson to its committed manuscripts without changing a source file.
>
> **What you finished last time:** a modern decoder contract whose vocabulary and context fields are waiting for data. Kernels do not share memory, so this notebook rebuilds every data decision from disk.
>
> **What this notebook delivers:** `artifacts/base-lm/tokenizer/`, `train.bin`, `validation.bin`, and `dataset-manifest.json` for Notebook 06. The main path uses diagrams, measured plots, and animations instead of derivations.

## 0. The Challenge and Scope

> **The mission:** Riverside House - turn committed chapters into a reproducible, leakage-checked next-token stream while preserving every manuscript byte.

**What we know so far:** Riverside has a decoder architecture and a folder of prose. **But a folder is not a dataset:** it has no frozen split, tokenizer identity, boundary token, packing rule, shard hash, or reload proof.

**What's blocking us:** token-level splitting leaks adjacent prose, tokenizer fitting can quietly see validation text, duplicate chapters can cross the boundary, and naive padding spends blocks practicing nothing.

**What this chapter unlocks:** document ownership before fitting, transparent contamination diagnostics, a training-only byte-level BPE tokenizer, fixed-length shards, and a manifest that can refuse altered bytes.

## 0 · The Challenge

> **The mission**: Riverside House — turn one randomly initialized modern decoder into a validated, reloadable base-model checkpoint using only the frozen local corpus artifacts.

**What we know so far:**
- Notebook 05 defines a tokenizer, separate train and validation shards, and their SHA-256 identities.

**What's blocking us:** a loss curve alone is not enough. You need digest refusal, finite-state checks, gradient coverage, accumulation accounting, resumable optimizer and RNG state, validation-only checkpoint selection, and final reload parity.

**What this chapter unlocks:** one small base-model artifact whose lineage and limitations are explicit. It does not create an assistant.
