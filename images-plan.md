## Copilot Image Generation Instructions

Use these instructions when asking Copilot to generate a pending asset. Generate
one image at a time so the filename, labels, and review feedback cannot drift
between assets.

paragraph or markdown cell immediately surrounding the planned image. Do not copy
raw notebook JSON with escaped quotes.

offers image generation and returns image attachments**. Model and product
availability can vary. If the chat can return only text or code, stop and open an
image-capable Copilot chat surface; do not ask it to approximate the asset with
SVG, Mermaid, HTML, or plotting code.

```text

Destination filename:
<EXACT repository-relative destination from images-plan.md>
```

### 2. Download using the exact destination name

Download the attachment directly to the destination in the pending row when the
chat supports choosing a save location. Otherwise download it once, then move it
to the exact destination before editing the chapter reference. Do not rename an
unrelated existing asset or keep a second copy with `(1)`, `_final`, or `_v2`
appended.

Examples:

```text
Correct: learning/genai/02-transformers/images/cross-attention-bridge.png
Wrong:   Downloads/cross-attention-bridge (1).png
```

If the destination directory does not exist, create only that directory:

```powershell
New-Item -ItemType Directory -Force "path/to/images" > $null
```

```bash
mkdir -p path/to/images
```

Do not create a second shared image folder or move neighboring assets.

### 3. Verify the downloaded file

From the repository root, use this cross-platform Python check. It reads the PNG
signature and dimensions without requiring Pillow or another package:

```powershell
@'
import struct
from pathlib import Path

path = Path("path/from/the/pending-row.png")
if not path.is_file():
  raise SystemExit(f"Missing generated image: {path}")
with path.open("rb") as stream:
  signature = stream.read(8)
  if signature != b"\x89PNG\r\n\x1a\n":
    raise SystemExit(f"Expected a real PNG file: {path}")
  length = struct.unpack(">I", stream.read(4))[0]
  chunk = stream.read(4)
  if chunk != b"IHDR" or length < 8:
    raise SystemExit(f"PNG has no valid IHDR header: {path}")
  width, height = struct.unpack(">II", stream.read(8))
if (width, height) != (1600, 900):
  raise SystemExit(f"Expected 1600x900, got {width}x{height}: {path}")
print(f"PASS: {path} ({width}x{height})")
'@ | python -
```

Then inspect the image in VS Code at full size and at roughly 50% zoom. Reject it
when labels are misspelled, an arrow can be read in more than one direction, text
blends into its background, the visual teaches a different mechanism, or any
required label is unreadable at notebook width.

If the image fails review, do not patch it manually unless the problem is a clean
crop. Return to the same Copilot chat, list at most three concrete defects, paste
the same destination filename, and ask for a replacement attachment. Overwrite
the rejected local file only after the replacement downloads successfully, then
repeat the format, dimensions, and visual checks.

### 4. Verify the reference

The chapter must use a relative path and descriptive alt text:

```markdown
![What the diagram shows and why the distinction matters](images/exact-kebab-case-name.png)
```

The **owning chapter** is the folder containing the Markdown file or notebook that
references the image. Run the repository link check on that file or folder:

```powershell
python scripts/check-md-links.py path/to/owning/chapter-or-directory
git diff --check -- path/to/owning/chapter-or-directory images-plan.md
```

For a notebook, also confirm that it remains valid JSON and that every Python
cell still parses:

```powershell
@'
import ast
import json
from pathlib import Path

path = Path("path/to/notebook.ipynb")
notebook = json.loads(path.read_text(encoding="utf-8"))
ids = [cell.get("id") for cell in notebook["cells"]]
if len(ids) != len(set(ids)):
  raise SystemExit("Notebook has duplicate cell IDs")
for index, cell in enumerate(notebook["cells"]):
  if cell.get("cell_type") == "code":
    ast.parse("".join(cell.get("source", [])), filename=f"{path}:cell-{index}")
print(f"PASS: {path} ({len(ids)} cells)")
'@ | python -
```

Image generation must not change notebook cell IDs, order, outputs, or executable
code. If the image or notebook check fails, keep the queue item `GENERATED`, fix
only the failing asset or reference, and rerun the failed check before continuing.

Change the row from `PENDING` to `VERIFIED` only after:

- `git diff` contains no accidental downloads, duplicate names, or unrelated files.

## Choosing Mermaid, Code, or a Generated Image

Do not create a static asset when the repository already has a better source of
truth:

- Use **Mermaid** for simple flows, ownership paths, state machines, and decision
  gates that remain readable as text in source control.
- Use **notebook code** for plots whose values come from executable data or model
  output. Do not replace measured charts with illustrative generated images.
- Use a **generated PNG** for a composition that Mermaid cannot express clearly,
  such as spatial tensor layouts, multi-panel mechanism comparisons, hardware
  geometry, or an annotated architecture with several simultaneous paths.

Never commit a broken image reference as a reminder. Put the proposed asset in
the pending queue first, generate and verify it, and add the chapter reference in
the same commit as the downloaded file.
